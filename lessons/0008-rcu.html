RCU:让读者零开销的同步魔法

这是知识储备篇的真正终章——讲完这课,你就集齐了读内核驱动和三大核心篇所需的全部基础。 RCU(Read-Copy-Update)是内核最精巧的同步机制:读者完全不加锁、零开销, 写者复制一份改、择机回收旧的。它撑起了路由表、进程链表、文件系统元数据等"读极多写极少"的核心数据结构。

这课的三个组件一起讲

RCU 主线(§B.2.12),外加你上一课留的两个 🟡/⬜ 点:

  • §B.2.6 禁抢占:因为 RCU 读侧免锁的根基就是 preempt_disable——两者天然咬合。
  • §B.2.3 内存屏障:因为 rcu_dereference 的精髓就是"恰好够用的内存顺序"——这正好把屏障讲透。

RCU 的核心思想:让写者付费,不让读者付费

第 7 课的所有锁(rwlock/seqlock/spinlock),读者都要付出某种代价(原子指令、缓存行抖动、重试)。RCU 反转这个思路:

传统锁(第 7 课)

读者和写者互相付费:读者加锁(原子操作、缓存同步),写者也加锁。读多时,读者之间的同步开销就大。

RCU

读者几乎不付费(无锁、无原子指令);写者付费——复制一份新数据、改、原子换指针,然后等一个宽限期再回收旧数据。

为什么能这样?因为读旧版本是安全的——只要旧数据还没被释放,持有旧指针的读者照样能正常读完。写者要做的是延迟回收,确保所有"正读着旧版本"的读者都退出了,再 kfree。

RCU 更新一次的时间轴(读侧零锁) 时间 ──────────────────────────────────────────────→ 读者 A: rcu_read_lock(); p = rcu_dereference(gptr); 用 p... rcu_read_unlock(); ↓ 写者在这期间换指针也没事,A 持的是旧 p,旧 p 还活着 写者 : new = kmalloc(...); *new = 改后的值; rcu_assign_pointer(gptr, new); // 原子换指针,新读者拿到 new synchronize_rcu(); // 等宽限期——等所有"持旧 p"的读者退出 /* 宽限期过后,确信读者 A 那种已经 unlock */ kfree(old); // 现在才能安全释放旧版本 读者 B(换指针后进入): rcu_read_lock(); p = rcu_dereference(gptr); // 拿到 new 关键:读者 A 在宽限期结束前不可能还在用 old,所以 kfree(old) 安全。

读侧三件套 + §B.2.6 禁抢占

// 读侧:标记临界区 + 安全取指针
rcu_read_lock();                              // 进入 RCU 读临界区
p = rcu_dereference(gptr);                    // 安全读取受 RCU 保护的指针
/* 用 p 访问数据,但不能睡眠(非可抢占 RCU 下) */
rcu_read_unlock();                            // 退出

为什么读侧不加锁就安全?这就是 §B.2.6 禁抢占登场的时刻——RCU 读侧免锁的根基:

内核配置rcu_read_lock() 实际做什么
非抢占(PREEMPT_NONE/VOLUNTARY)
WSL2 默认这类		 ≈ preempt_disable() + 编译器屏障。无原子指令、无缓存抖动。读者在这个核上不会被切走,所以"这个核一定在临界区内"可以由"它没经过静止状态"推断。
抢占(PREEMPT/PREEMPT_RT) 增加当前任务的嵌套计数(current->rcu_read_lock_nesting++),RCU 通过采样计数器判断宽限期。读侧仍无锁,但可被抢占。
§B.2.6 禁抢占(preempt_disable)的本质

preempt_disable() 阻止当前任务被抢占(不会被打断切走),直到 preempt_enable()。 它本身是个轻量同步手段——比锁便宜得多。RCU 借用它来"画"读临界区:读者持 preempt_disable 期间不会被切走, 所以一旦这个核发生上下文切换(静止状态),就证明它已经退出了所有 RCU 读临界区。这是宽限期判定的基础。

约束:非抢占 RCU 读临界区里不能睡眠(又见第 4 课铁律——禁抢占等价于原子上下文)。

写侧三件套 + §B.2.3 内存屏障

// 写侧:复制 → 改 → 原子换指针 → 等宽限期 → 释放旧版
struct foo *new = kmalloc(sizeof(*new), GFP_KERNEL);
*new = 改后的值;                          // 1. 复制并改
rcu_assign_pointer(gptr, new);            // 2. 发布:原子换指针(含写屏障)

// 方式 A:同步等(简单,但写者阻塞)
synchronize_rcu();                        // 3. 等一个宽限期
kfree(old);                               // 4. 安全释放

// 方式 B:异步回调(不阻塞,适合不能睡的热路径)
call_rcu(old, foo_rcu_free);              // 宽限期后自动调 foo_rcu_free(old)
// 或一步到位:
kfree_rcu(old, rcu_head_in_foo);          // 等价于 call_rcu + kfree

为什么 rcu_assign_pointer 和 rcu_dereference 要成对出现?这就是 §B.2.3 内存屏障登场的时刻——

数据发布/订阅的内存顺序问题 写者: 读者: new->data = 42; p = gptr; // 可能先看到新指针 rcu_assign_pointer(gptr, new); print(p->data); // 但 p->data 还是旧值/未初始化! CPU 和编译器都可能乱序:new->data=42 可能在 gptr=new 之后才对其他核可见。 读者看到了新指针,却读到新数据还没写入的字段——错。 rcu_assign_pointer 在换指针前插写屏障(保证 data 先于指针可见); rcu_dereference 在取指针后插读屏障/依赖屏障(保证先取指针、再取其指向的数据)。 两者配合 = 发布-订阅顺序正确。
§B.2.3 内存屏障的本质(收尾)

编译器和 CPU 都会乱序内存访问以追求性能。需要严格顺序时插屏障:

  • smp_wmb():本核之前的写,先于之后的写对其他核可见(写屏障)。rcu_assign_pointer 内含它。
  • smp_rmb():本核之前的读,先于之后的读(读屏障)。rcu_dereference 在 DEC Alpha 上含它,其他架构靠地址依赖顺序。
  • smp_mb():读写都屏障(最重)。

给读 RCU 代码的你:看到 rcu_assign_pointer / rcu_dereference 成对出现,就知道作者已经处理好了发布-订阅顺序——你不用再操心屏障。这也是为什么 RCU 提供这两个宏而不让你裸读写指针。

宽限期(grace period):写者的等待

宽限期 = 所有 CPU 都至少经过一次静止状态(quiescent state,如上下文切换、进入 idle、用户态返回)的时间窗。 经过静止状态意味着该核退出了任何之前开始的 RCU 读临界区。

宽限期的判定 写者调 synchronize_rcu() ──────→ 宽限期开始 CPU0: ──[读者 A 在临界区]──(上下文切换)── ← 静止状态,A 必已 unlock CPU1: ──[读者 B 在临界区]──(上下文切换)── ← 静止状态 CPU2: ──(idle)── ← idle 也是静止状态 ──────→ 宽限期结束,synchronize_rcu() 返回 此刻,所有"换指针前就在读"的读者都不可能还在用 old → kfree(old) 安全。

代价:写者要等宽限期(典型毫秒级),所以 RCU 不适合频繁写的场景,只适合"读极多、写极少"。

RCU vs seqlock:都是读多写少,区别?

对比seqlock(第 7 课)RCU
读者开销无锁,但读失败要重试无锁、无重试,读到的一定是某个一致的快照
读者阻塞写?不阻塞不阻塞
写者开销加写锁、序号++复制一份 + 换指针 + 等宽限期 + 释放旧版
典型用途简单值(时间戳、统计)指针/复杂数据结构(链表、树、路由表)
读者看到什么可能读到中间值,重读稳定的旧版本或新版本,不需重读

选型:简单数值用 seqlock(读者轻,重试无妨);复杂结构/指针用 RCU(读者要稳定遍历、不能重试)。

动手实验:RCU 保护一个链表(WSL2 可跑)

目标:用 RCU 保护一个全局链表头。加载时建 3 个节点,模块里用 synchronize_rcu + kfree_rcu 演示"换头+延迟回收"。这是你第一次写读侧零锁的代码——感受读者不持任何锁就能安全遍历。 

// bt_rcu.c — 第 8 课实验:RCU 保护全局链表头
#include <linux/module.h>
#include <linux/kernel.h>
#include <linux/slab.h>
#include <linux/list.h>
#include <linux/rcupdate.h>

struct bt_item {
    int              v;
    struct list_head list;
};

/* 受 RCU 保护的全局链表头指针(指向一个动态分配的 head 节点结构) */
static struct list_head __rcu *g_head;

/* 读者:零锁遍历 */
static void reader(void)
{
    struct list_head *head;
    struct bt_item *it;

    rcu_read_lock();
    head = rcu_dereference(g_head);          // 安全取指针
    list_for_each_entry(it, head, list)      // 遍历——不持任何锁!
        pr_info("bt_rcu 读: v=%d\n", it->v);
    rcu_read_unlock();
}

/* 写者:整体替换链表头(模拟"换一份数据"),旧的延迟释放 */
static void replace_head(struct list_head *new_head)
{
    struct list_head *old;
    old = rcu_dereference_protected(g_head, lockdep_is_held(&some_lock)); // 写侧用 protected 版
    rcu_assign_pointer(g_head, new_head);    // 发布新指针
    synchronize_rcu();                       // 等宽限期
    kfree(old);                              // 安全释放旧 head
}

static int __init bt_rcu_init(void)
{
    struct list_head *h;
    int i;
    h = kmalloc(sizeof(*h), GFP_KERNEL);
    INIT_LIST_HEAD(h);
    for (i = 0; i < 3; i++) {
        struct bt_item *it = kmalloc(sizeof(*it), GFP_KERNEL);
        it->v = i;
        list_add_tail(&it->list, h);
    }
    rcu_assign_pointer(g_head, h);
    pr_info("bt_rcu: 加载,读一次:\n");
    reader();
    return 0;
}

static void __exit bt_rcu_exit(void)
{
    struct list_head *h = rcu_dereference_protected(g_head, 1);
    struct bt_item *it, *tmp;
    list_for_each_entry_safe(it, tmp, h, list) {
        list_del(&it->list);
        kfree(it);
    }
    synchronize_rcu();
    kfree(h);
    pr_info("bt_rcu: 卸载\n");
}
module_init(bt_rcu_init);
module_exit(bt_rcu_exit);
MODULE_LICENSE("GPL");
MODULE_DESCRIPTION("Lesson 8: RCU-protected list demo");
观察重点

reader() 里没有任何锁——rcu_read_lock 在非抢占内核下连原子指令都没有。这就是"读者零开销"的真实代码。 你以后读网络协议栈、路由表、进程 task_struct 链表的代码,全是这个模式。
