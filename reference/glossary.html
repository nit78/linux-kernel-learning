术语表（Glossary）

随课程扩充 已收录 50 条 ← 回到第 1 课

Linux 内核核心术语。每条只给紧定义（"它是什么"），配英文原词与应避免的同义混淆。 课程里出现这些词时一律用本表的词。新术语随课程加入。

运行模型与特权级

内核态 kernel mode / kernel space execution
CPU 运行在最高特权级（x86 的 ring 0、ARM 的 EL1），可执行特权指令、访问全部内存与硬件。 内核代码与驱动模块都在内核态运行。 避免叫"特权模式""管理模式"（ARM 的 EL1 才叫 management，易混）。
用户态 user mode
CPU 运行在低特权级（x86 的 ring 3、ARM 的 EL0），受 MMU 与权限隔离约束， 不能直接执行特权指令或访问硬件，必须通过系统调用进入内核态。 避免叫"应用态"。
内核空间 kernel space
虚拟地址空间中专供内核使用的高地址区段（如 x86-64 默认上半部）。 所有进程共享同一份内核空间映射。 区分：内核态指"运行特权级"，内核空间指"地址区段"。一个讲 CPU 状态，一个讲地址。
上下文 context
当前代码运行所处的"身份与限制"环境。内核中主要有两类： 进程上下文（process context，可睡眠、可被抢占、可访问当前进程资源） 与 中断上下文（interrupt context，不可睡眠、与任何进程无关）。 避免把"上下文"等同于"寄存器快照"——后者只是上下文切换时保存的具体内容。

内核模块与代码组织

内核模块 kernel module (.ko)
一段可在运行时用 insmod/modprobe 加载、用 rmmod 卸载的内核代码， 编译产物是 .ko（kernel object）。驱动和部分子系统常以模块形式存在， 避免把一切编进内核镜像。 避免叫"驱动文件"——模块不一定都是驱动，驱动也不一定都是模块（可编进 vmlinux）。
vmlinux vmlinux
编译产生的、未压缩的内核可执行镜像（ELF），包含所有静态链接进内核的代码与数据。 启动时加载到内存运行的就是它（常被压缩成 bzImage / Image）。
系统调用 system call / syscall
用户态进入内核态的受控入口，是一组编号固定的内核服务函数（如 read、open）。 用户程序通过它请求内核代做特权操作。

数据结构（第 1–2 课重点）

侵入式链表 intrusive / embedded linked list
一种链表组织方式：链表节点本身不持有数据，节点（如 struct list_head） 被嵌入到宿主数据结构内部。同一宿主可同时挂在多条链表上， 且链表代码与数据类型解耦。Linux 内核统一采用这种方式。 避免叫"通用链表""容器链表"——后者特指节点持有数据的相反风格。
struct list_head struct list_head
内核双向循环链表的节点类型，只含两个指针：next 与 prev。 它是侵入式链表的载体，被嵌入到几乎所有需要"串起来"的内核结构体中。
container_of container_of
内核头文件提供的一个宏：给定"嵌入成员的指针、宿主类型、成员名"， 返回宿主结构体的首地址。原理是用 offsetof 把成员指针反向减去偏移量。 它是侵入式链表能从 list_head* 取回宿主的关键。
task_struct task_struct
内核中描述一个"可调度执行单元"（进程或线程，内核不严格区分）的核心结构体， 是进程的进程控制块。调度、内存、信号、文件等子系统都围绕它组织。 避免叫"PCB"——内核源码里就叫 task_struct，"PCB"是教科书术语。

中断与时间

中断服务例程 ISR — Interrupt Service Routine
硬件中断发生时内核调用的、与某中断号绑定的处理函数。运行在中断上下文， 必须快速返回、不可睡眠。内核里它通常分"上半部"（硬中断，立即执行） 和"下半部"（软中断 / tasklet / 工作队列，延迟执行）。 避免叫"中断回调"——回调一般指软件注册的异步通知，ISR 特指硬件中断路径。
软中断 softirq
内核提供的"延迟执行"机制，把可在硬中断之外完成的工作推迟处理， 仍在中断上下文、不可睡眠。tasklet 与 timer 都建立在软中断之上。 避免与"信号"（signal，用户态异步通知）混淆——软中断是内核内部机制。
上半部 / 下半部 top half / bottom half
中断处理的分工：上半部 = 硬中断 ISR，只做最紧急的事（如确认中断、拷贝数据）； 下半部 = 延迟完成的工作（如协议处理、唤醒进程），由软中断 / tasklet / 工作队列承载。 这样能尽快重新打开中断、提高系统响应能力。

哈希与 hlist（第 2 课）

哈希桶 hash bucket
哈希表数组的单个元素。每个桶挂一条"冲突链"——所有哈希到同一个桶的元素串在这条链上。 哈希表 = 桶数组 + 每桶上的链表。桶数通常是 2 的幂。
struct hlist_head / hlist_node hlist — hash list
内核为哈希表特制的链表类型。hlist_head 只有 first 一个指针 （为成千上万的桶节省一半头内存）；hlist_node 的 pprev 是双指针， 指向"指向我的那个链域"（桶头的 first 或前一节点的 next）， 使删除任意节点无需特判桶头。 避免把 hlist 当通用双向链表用——它专为哈希桶设计，不循环。
pprev（双指针） pointer-to-pointer back link
hlist_node 里指向前一链域地址的字段。它不是指向前一个节点，而是指向"指向前一个节点的那个指针"。 因此 *pprev = next 这一句在头节点和中间节点上都成立，删除操作统一为无分支代码。 这是 C 双指针在内核里的经典用例。

红黑树与有序结构（第 3 课）

红黑树 red-black tree, rbtree
一种自平衡二叉搜索树，每个节点带红/黑颜色，靠 5 条性质保证最长路径不超过最短路径的两倍， 查找/插入/删除均为 O(log n)。内核用它存储有序、需频繁增删查的集合 （调度器就绪队列、ext4 区段树、timerfd 等）。与 list_head 一样采用侵入式：节点嵌入用户结构体。
struct rb_node / rb_root kernel rbtree node / root
内核红黑树的节点与根类型。rb_node 含 __rb_parent_color（父指针 + 颜色合用一个字）、 rb_left、rb_right。rb_root 只含一个指向根节点的指针，用 RB_ROOT 初始化。 设计哲学：内核只提供节点 + 平衡算法（rb_insert_color/rb_erase），比较与定位插入位置由使用者自己写——避免热路径的间接调用开销。
黑高 black-height
红黑树性质 5 的核心概念：从某节点到其所有后代叶子（NULL）路径上的黑节点数量。 红黑树要求同一节点的所有路径黑高相同，这是保证平衡的数学基础。
EEVDF Earliest Eligible Virtual Deadline First
Linux 6.6 起取代 CFS 的 CPU 调度算法。仍在 cfs_rq 里用 rbtree（tasks_timeline）， 但排序键从 CFS 的 vruntime 改为虚拟截止时间。EEVDF 还引入"资格"判定。 避免再说"6.6 还在用 CFS / 按 vruntime 排"——已过时。
CFS Completely Fair Scheduler
Linux 2.6.23 起的"完全公平调度器"，核心是用 rbtree 按 vruntime 排序就绪任务，最左（vruntime 最小）者先跑。 6.6 起 EEVDF 取代了 CFS，但代码仍沿用 cfs_rq / tasks_timeline / sched_entity 结构，只是算法变。 本书的调度篇（§14）以 CFS 为主线，读时需对照 EEVDF 的版本演进。
maple tree maple tree
一种 RCU 安全、基于 B 树、缓存友好的区间树，专为存储非重叠地址区间设计。 6.1 起用它取代了 mm_struct 里组织 VMA 的 rbtree + 链表（mm_mt 字段）。 6.6 迁移完成。避免再说"VMA 用红黑树"——6.1 起已过时。注意：调度器仍用 rbtree，maple tree 只取代了 VMA 那处。

中断与延迟执行（第 4 课）

进程上下文 / 中断上下文 process context / interrupt context
内核代码运行时所处的两种"身份"。进程上下文：代表某进程执行（如系统调用、workqueue 工作函数、threaded IRQ 的线程）， 有 current 指向一个真实 task_struct，可以睡眠、可以持有 mutex。 中断上下文：硬中断 ISR、softirq、tasklet——不属于任何进程，current 只是"借住"在被打断的进程上， 绝对不能睡眠。判断当前在哪种上下文是写驱动最基本的能力。
硬中断 / 上半部 hardirq / top half
硬件触发的中断服务程序（ISR），由 request_irq/request_threaded_irq 的 handler 参数注册。 跑在中断上下文，不能睡眠，只做最紧急的事（应答中断、拷贝数据、唤醒下半部），尽快返回以重新开放中断。
softirq software interrupt
内核内部使用的低延迟延迟执行机制，跑在中断上下文（不可睡眠）。向量在编译期固定（NET_RX、NET_TX、TIMER、RCU 等）， 驱动极少直接使用。tasklet 建在它之上（占两个 softirq 向量）。 避免与"信号"（signal，用户态异步通知）混淆；避免与"软中断（x86 INT 指令）"混淆。
tasklet tasklet
建在 softirq 之上的延迟执行机制，跑在中断上下文、不可睡眠。2024 年起正式废弃（LWN: The end of tasklets）， 内核正在把 in-tree 驱动从 tasklet 迁到 BH workqueue 或 threaded IRQ。 新代码不要用；但移植/读老驱动时仍会大量见到，要能看懂。
workqueue / 工作队列 workqueue
延迟执行机制，工作函数跑在进程上下文（内核线程），可以睡眠、持有 mutex、做 I/O。 现代 API：alloc_workqueue(name, flags, max_active) 创建队列，INIT_WORK/INIT_DELAYED_WORK 初始化工作， queue_work/queue_delayed_work 提交。是驱动下半部最常用的机制。 卸载时必须 cancel_work_sync / cancel_delayed_work_sync 取消未决工作，否则 oops。
threaded IRQ / 线程化中断 threaded interrupt handler
由 request_threaded_irq(irq, handler, thread_fn, ...) 注册的中断处理模型： handler（上半部）只屏蔽中断 + 唤醒一个内核线程并返回 IRQ_WAKE_THREAD； thread_fn（下半部）跑在进程上下文，可睡眠、可做 I/O（如 I²C/SPI 读寄存器）。 现代驱动首选，尤其当中断处理需要睡眠时。request_irq 自 ~4.5 起只是 thread_fn=NULL 的 request_threaded_irq。

时间与定时器（第 5 课）

jiffies jiffies
内核全局变量，记录自启动以来的 tick 数。每个 tick 中断里自增。是低精度时间的统一度量。 jiffies 实际是 jiffies_64（64 位计数器）的低 32 位别名；64 位系统上二者等价，32 位上约 50 天回绕。 避免用裸 > 比较 jiffies——会因回绕出错，必须用 time_after/time_before。
HZ HZ
编译期常量（CONFIG_HZ），表示每秒的 tick 中断次数。1 jiffy = 1/HZ 秒。 x86_64 upstream defconfig 默认 1000（服务器发行版常 250）。HZ 越高响应越好但开销越大。 驱动里"100ms"必须经 msecs_to_jiffies(100) 转成 jiffies 数才能用。
timer_list（时间轮） timer wheel / low-resolution timer
内核的低精度定时器，基于 jiffies，粒度 1/HZ 秒。内部用哈希时间轮（多级级联）组织。 6.x 起 API：timer_setup(t, cb, flags)，回调签名是 void cb(struct timer_list *) （老 setup_timer + data 字段已移除），私有数据用 from_timer()（即 container_of）反查。 适合网络重传、协议超时等粗粒度场景。
hrtimer（高精度定时器） high-resolution timer
内核的高精度定时器，基于 ktime_t（纳秒），独立于 jiffies/HZ。 定时器存在红黑树里按到期时间排序（O(log n) 插入，O(1) 取最左最快到期）—— 正是 rbtree 的真实用武之地。 API：hrtimer_init / hrtimer_start / hrtimer_forward_now， 回调返回 HRTIMER_RESTART 重排或 HRTIMER_NORESTART 停止。 用于多媒体、实时等需要 µs 精度的场景。
ktime_t ktime_t
hrtimer 用的纳秒级时间类型。ktime_set(秒, 纳秒) 构造，例如 ktime_set(0, 1000000) = 1ms。 与 jiffies（tick 数）不同，它是绝对时间量。
delay 家族 udelay / mdelay / usleep_range / msleep
"等一会儿"在内核里有忙等与睡眠两种： udelay(n)（忙等 µs，原子上下文可用）、mdelay（忙等 ms，不推荐）； usleep_range(min, max)（睡眠，10µs–20ms 首选）、msleep(n)（睡眠，>20ms）。 后两者仅进程上下文可用（会睡眠）。选型口诀跟第 4 课"能不能睡眠看上下文"是同一条铁律。

设计模式（第 6 课）

模板方法设计模式 Template Method pattern
定义一个流程的骨架（模板），把某几个步骤的具体实现延迟到使用者填。 内核里典型落地：函数指针表（如 file_operations、vm_operations_struct、 net_device_ops）。VFS/通用框架管"流程怎么走"，各驱动/文件系统把实现填进对应函数指针槽—— 这就是 C 版的"接口 + 多态"。读内核遇到 xxx_op/xxx_ops 命名的结构体，多半是模板方法。
观察者设计模式 Observer pattern
被观察者维护一个订阅者列表，有事时统一通知；观察者被动接收、无需轮询。解耦"事件源"和"关心它的人"。 内核落地是通知链（notifier chain）。xxx_notify 多半是被观察者， register_xxx_notifier/xxx_listener 多半是观察者。
file_operations struct file_operations
VFS 提供的"文件操作模板"——一个全是函数指针的结构体（open/read/write/mmap/release/fault…几十个槽）。 各文件系统/驱动实例化一份，填入自己的实现。是模板方法模式在内核里最高频的载体。 6.x 演进：经典的 mmap 回调正在被 mmap_prepare + 基于 fault 的模型取代（见 LWN 1038715）。
vm_operations_struct struct vm_operations_struct
VMA（虚拟内存区域）的操作表，另一组模板。关键是 fault 回调：mmap 只登记 VMA， 进程真正访问时触发缺页异常，内核调 vm_ops->fault() 才分配物理页（懒分配）。 是第 8 章缺页异常的接口入口。
notifier chain / 通知链 notifier chain
内核的观察者模式原语。由 notifier_block 串成的单链，每节点含一个回调。 四种变体：blocking（rwsem，进程上下文，可睡眠）、atomic（spinlock，中断上下文，不可睡）、 SRCU、raw（无锁）。API：BLOCKING_NOTIFIER_HEAD、blocking_notifier_chain_register、 blocking_notifier_call_chain。典型链：module、netdev、reboot、cpu、panic。 回调返回 NOTIFY_OK/NOTIFY_DONE/NOTIFY_STOP/NOTIFY_BAD 控制遍历。

内核同步（第 7–8 课）

竞争 race condition
多个执行流（CPU 核、中断、线程）同时访问同一份共享数据，至少一个是写，且未加同步保护 → 结果不确定。 内核竞争来源三维度叠加：多 CPU 核 + 中断 + 抢占。
临界区 critical section
访问共享数据的代码段，必须用同步原语（锁、原子操作等）保护，使其对其他执行流看起来是原子不可分割的。
每 CPU 变量 per-CPU variable
免锁手段：每个 CPU 核持有一份独立副本，写自己的不会竞争。API：DEFINE_PER_CPU、 this_cpu_inc、per_cpu(var, cpu)。适合高频计数/统计。要总数时跨核汇总才需考虑同步。
atomic_t atomic variable
单变量的原子读-改-写原语，跨核免锁。API：atomic_inc、atomic_add、 atomic_read、atomic_inc_return。比 percpu 重（跨核），但比锁轻。
READ_ONCE / WRITE_ONCE READ_ONCE / WRITE_ONCE
对单变量并发读写（只需读/写本身不被编译器拆碎，不要求读-改-写原子）的现代推荐原语。防编译器撕裂/融合/消除， 相当于 C11 的 memory_order_relaxed。内核明确不推荐裸 volatile，用这两个代替。
内存屏障 memory barrier
强制 CPU/编译器按指定顺序执行内存访问的指令。smp_mb()（全屏障）、smp_rmb()（读）、smp_wmb()（写）。 因为编译器和 CPU 都会乱序读写以求性能，需要严格顺序时插屏障。日常多用 READ_ONCE/WRITE_ONCE 即可。
自旋锁 spinlock
抢不到就忙等（CPU 空转循环重试），绝不睡眠。适用短临界区、中断上下文可用。 四变体：spin_lock（锁绝不沾中断）、spin_lock_bh（关软中断）、 spin_lock_irq（关中断）、spin_lock_irqsave（关中断+存状态，最通用安全）。 持锁期间绝不能睡眠，否则死锁。
互斥锁 mutex
抢不到就睡眠让出 CPU，被唤醒后再来。适用长临界区、仅进程上下文（会睡）。 API：DEFINE_MUTEX、mutex_lock、mutex_unlock。 中断上下文绝不能用——会睡眠导致死锁。
信号量 semaphore
可作"计数信号量"（允许 N 个执行流同时进）或互斥（初值 1，此时类似 mutex）。API：sema_init、down、up。 会睡眠，仅进程上下文。mutex 是更严格的互斥（多了调试/类型检查），新代码优先 mutex。
读写锁 rwlock
读多写少场景：多个读者可并发持有读锁，写者独占。比普通锁让读者不互斥。但写仍需等所有读完成。
顺序锁 seqlock
读多写少、且读者不要阻塞写的场景：读者不加锁，只在读前后读序号，中途序号变就重读； 写者独占、写时序号++。典型用于时间戳、统计。比 rwlock 更让写者畅通。
禁抢占 preempt_disable
preempt_disable() 阻止当前任务被抢占（不被打断切走），直到 preempt_enable()。 轻量同步手段，比锁便宜。禁抢占等价于原子上下文，期间不能睡眠（又见第 4 课铁律）。 RCU 读侧免锁的根基：非抢占内核里 rcu_read_lock ≈ preempt_disable + 编译器屏障。
RCU Read-Copy-Update
内核最精巧的同步机制，专为"读极多写极少"优化。读者完全不加锁、零开销（非抢占内核下 rcu_read_lock 连原子指令都没有）；写者复制一份、原子换指针、等一个宽限期再回收旧版。 哲学：不让读者付费，让写者付费。撑起路由表、进程链表、文件系统元数据等核心结构。 API：rcu_read_lock/rcu_read_unlock（读侧）、rcu_dereference（安全取指针）、 rcu_assign_pointer（发布）、synchronize_rcu/call_rcu/kfree_rcu（写侧等宽限期+回收）。
宽限期 grace period
RCU 的核心概念：所有 CPU 都至少经过一次静止状态（quiescent state，如上下文切换、idle、用户态返回）的时间窗。 经过静止状态意味着该核退出了之前开始的任何 RCU 读临界区。synchronize_rcu() 阻塞等一个宽限期， 返回后即可安全释放旧数据（所有持旧指针的读者都已退出）。代价是写者延迟（毫秒级），故 RCU 不适合频繁写。
