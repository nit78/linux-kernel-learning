# 第 4 课主题：中断（LR-0005）

**Status:** active

## 决策
第 4 课进入知识储备篇 §3 **中断**。这是用户 MCU 经验大规模迁移的关键课，也是后续所有驱动开发的根基。

## 用户背景与迁移点
- 用户有蓝牙/WiFi 驱动**移植**经验 + 扎实 MCU/裸机背景 → 对"中断"概念不陌生，但要迁移到内核的"上半部/下半部"分工思维。
- 已知用户能独立啃 WSL2 内核编译、能精准复述 pprev、能选"原理+真实"——**第 4 课可直入真实内核 IRQ API，不绕弯子**。

## 必须核验的版本敏感点（不能靠记忆）
1. **tasklet 在 6.6 的状态**：老书常说 tasklet，但内核一直在讨论废弃 tasklet（[clean up tasklet] 系列 patch）。需确认 6.6 里 tasklet 是否还可用、是否已开始移除。
2. **request_threaded_irq**：线程化中断是现代驱动推荐做法，需确认 API 与现状。
3. **workqueue 现状**：并发工作队列（ccwq）是默认，需确认 alloc_workqueue 接口。
4. **WSL2 限制**：用户的 6.6.87.2 WSL2 内核**无真实硬件中断**——IRQ 注册实验可能跑不了真实中断。需要设计一个不依赖硬件中断的实验（用软件触发，如 `raise_softirq` 或 workqueue 自调度）。

## 教学结构（沿用既定模式：最小够用知识 + 动手 win + 等长 quiz）
1. 为什么内核要把中断拆"上半部/下半部"（对照 MCU 的 ISR 经验——核心迁移点）。
2. 四种延迟执行机制对照：softirq / tasklet / workqueue / threaded IRQ（各自能做什么、不能做什么、何时用哪个）。
3. 真实 API：`request_irq` / `request_threaded_irq` / `disable_irq` 等。
4. 实验（WSL2 可跑）：用 **workqueue + 自调度**做周期性任务，不依赖硬件中断——这是 WSL2 上唯一能真实动手的"下半部"实验。
5. 明确标注：依赖真实硬件 IRQ 的实验（注册一个 GPIO 中断、PCI MSI）在 WSL2 跑不了，留到真机。
