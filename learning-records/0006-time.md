# 第 5 课主题：时间子系统（LR-0006）

**Status:** active

## 决策
第 5 课进入知识储备篇 §4 **Linux 的时间**。这是知识储备篇的**最后一站**——学完它，用户就完成了"MCU 思维 → 内核思维"的迁移地基，下一步进入内存管理篇。

## 用户背景与迁移点
- 用户有扎实 MCU 背景 → 熟悉 SysTick/定时器中断、jiffies 概念在 MCU 上有对应物（tick count）。
- 已写过蓝牙/WiFi 驱动移植 → 一定见过 `msecs_to_jiffies`、`mdelay`/`udelay`，但不一定理解为什么内核有两套定时器。
- 这是高迁移杠杆点：**把"MCU 的 tick 计数 + 硬件定时器"对照到"内核的 jiffies + hrtimer"**。

## 必须核验的版本敏感点（不能靠记忆）
1. **jiffies vs jiffies_64**：6.x 里的真实关系（jiffies 是 jiffies_64 的低 32 位别名）。
2. **HZ 的典型值**：x86 默认 250（不是老书的 100 或 1000），需确认。
3. **timer_list vs hrtimer**：两套定时器的本质区别（基于 jiffies/tick vs 基于高精度时钟、红黑树）。
4. **timer_list API 演进**：老接口 `setup_timer` / `init_timer` + 回调签名变化（6.x 起 timer 回调签名是 `struct timer_list *`，不再是 unsigned long data）。
5. **hrtimer API**：`hrtimer_init` / `hrtimer_start` 的现代签名。
6. **delay vs sleep**：`udelay`/`mdelay`(忙等) vs `msleep`/`usleep_range`(睡眠) 的选型。

## 教学结构
1. 内核"时间"的两层抽象：tick（jiffies，低精度）+ 高精度时钟（hrtimer）。
2. MCU 对照：SysTick → jiffies；硬件定时器 → hrtimer。
3. jiffies / HZ / msecs_to_jiffies 的真实用法。
4. timer_list（低精度） vs hrtimer（高精度）：本质区别、何时用哪个。
5. 实验（WSL2 可跑）：用 hrtimer 做周期任务，对比第 4 课的 workqueue 延迟方案。
6. delay 家族：udelay/mdelay/msleep 何时用哪个。
