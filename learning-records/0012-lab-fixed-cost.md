# 用户发现：第 7 课实验的措辞误导（LR-0012）

**Status:** active

## 用户原话
"动手实验:percpu vs spinlock 的开销(这个不还就是单个线程跑吗,没有竞争,锁也存在开销吗"

## 评估
用户说对了一半——实验确实单核单线程跑，**没有真正锁竞争**。但用户的隐含假设"没竞争 → 锁没开销"是**错的**：锁即使无竞争，仍有显著的**固定开销**（关中断 + 带 lock 前缀的原子指令独占缓存行 + 屏障；解锁再来一遍）。

**我的失误**：原 callout 把 spinlock 慢的原因写成"关中断 + 原子操作 + (可能)等别的核"，最后一项暗示了竞争，而实验根本测不到竞争。措辞误导，让用户合理地质疑了实验设计。应讲准"测的是固定开销，不是竞争"。

## 修正（已完成）
1. **实验介绍**前加 warn callout，明说"单核跑、无竞争"，并解释锁的固定开销构成（关中断 + lock 前缀原子指令 + 屏障）。
2. **结尾观察 callout** 重写：明确"差距全来自固定开销，跟竞争无关"。
3. **新增"进阶(可选):多核竞争实验"**：用 kthread 起多个内核线程抢同一把锁，NTHREADS 从 1→2→4，测真正的竞争开销（cache line bouncing + 忙等）。两个实验合起来，用户对锁开销的理解才完整。

## 教学教训（写进 NOTES 的元规则）
实验代码要**明确告诉用户"这个实验在测什么、不在测什么"**。否则像本例，用户合理质疑实验设计，反而暴露我的措辞不严谨。规则：
- 实验必有"在测 X / 不在测 Y"的明确声明。
- 若 Y 是用户可能误以为在测的东西，主动澄清。
